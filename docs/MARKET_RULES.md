# BTCBet market rules

All rounds are five minutes, aligned to Unix time multiples of 300 seconds. The configured cutoff defaults to 15 seconds before end. Only an exact receipt strictly before cutoff is eligible; intent creation alone is insufficient. The provider receipt timestamp is authoritative. Receipts predating the intent, or first reconciled after financial settlement, are refunded conservatively. The worker reconciles before settling.

Coinbase Exchange BTC-USD `ticker` WebSocket is the sole price source. Each accepted ticker is stored with provider time, receipt time, trade ID and normalized payload. Ticker is a sampled/batched trade feed, not an exhaustive trade log. Initial stale ticker snapshots are rejected. A valid observation has positive decimal price, receipt lag <=2 seconds and provider future skew <=1 second. Each resolution window requires at least three distinct stored observations. The first five seconds determine opening, final five seconds determine closing using the median. Even-count medians average the two center values using decimal arithmetic. Settlement waits three seconds after end for bounded feed receipt delay. No fallback feed or artificial historical ticks. If a window is insufficient, the round is voided. A brief disconnect does not itself void a window if sufficient valid observations exist.

Closing >= opening means UP, including a tie. Closing < opening means DOWN. One-sided pools are voided regardless of outcome. Empty rounds record an outcome when observations suffice but create no payments.

Presets default to 1,000, 5,000 and 10,000 sats. Exactly one accepted wager per agent per round, enforced by a partial unique index retaining acceptance through settlement. Outstanding intents reserve daily limits; zero house fee. Underpayments and overpayments are refunded **in full**, not aggregated. Additional payments on an already accepted wager are separately refunded without altering its position. Late receipts are never included in pools.

For a two-sided pool, each winner gets floor(stake * totalPool / totalWinningStake). Remaining sats go by largest fractional remainder, ties by ascending stable bet ID. Integer bigint math conserves every sat; API aggregate sats use decimal integer strings so JavaScript cannot truncate large amounts. Input preset amounts use safe JSON integers. UI pool percentages are indicative; estimated returns do not promise execution prices.

Round states: UPCOMING → OPEN → LOCKED → RESOLVED → PAYING → PAID, or VOIDED → REFUNDING → REFUNDED. Empty rounds finish directly. Bet transitions distinguish AWAITING_PAYMENT, ACCEPTED, LOST, PAYOUT_PENDING, PAID_OUT, REFUND_PENDING, REFUNDED and EXPIRED. Payment observations and rejection causes (including LATE_PAYMENT) are separate immutable receipt records and audit events rather than ambiguous transient bet states.
